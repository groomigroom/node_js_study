자바스크립트에서 콜백(Callback) 함수는 다른 함수의 인자(매개변수)로 넘겨주는 함수를 의미합니다. [1, 2] 
쉽게 말해 "이 작업이 끝나면, 내가 넘겨준 이 함수를 나중에 다시 불러줘(Call back)"라고 컴퓨터에게 부탁하는 것과 같습니다. [3, 4] 
------------------------------
## 💡 왜 사용할까요?

   1. 비동기 작업 처리: 자바스크립트는 서버에서 데이터를 가져오거나 시간이 걸리는 작업을 기다려주지 않고 다음 코드를 실행합니다. 이때 "데이터 다운로드가 끝나면 이 함수를 실행해줘"라고 제어하기 위해 사용합니다.
   2. 코드의 재사용성과 유연성: 하나의 함수에 서로 다른 콜백 함수를 넘겨줌으로써 다양한 동작을 수행하도록 만들 수 있습니다. [5, 6] 

------------------------------
## 💻 간단한 코드로 이해하기## 1. 일반적인 동기적(Synchronous) 콜백
넘겨주자마자 그 자리에서 바로 실행되는 방식입니다. [7] 

function greet(name, callback) {
    console.log("안녕하세요, " + name + "님!");
    callback(); // 인자로 받은 함수를 여기서 실행합니다.
}
function sayGoodbye() {
    console.log("다음에 또 만나요!");
}
// greet 함수를 호출할 때, sayGoodbye 함수를 인자로 넘깁니다.
greet("철수", sayGoodbye);
// 출력 결과:// 안녕하세요, 철수님!// 다음에 또 만나요!

## 2. 비동기적(Asynchronous) 콜백
특정 시간이 지나거나 작업이 완료된 후 실행되는 방식입니다.

console.log("1. 주문을 받습니다.");
// 3초(3000ms) 후에 콜백 함수를 실행합니다.
setTimeout(function() {
    console.log("2. ☕ 커피가 완성되었습니다!");
}, 3000);

console.log("3. 다른 손님의 주문을 받습니다.");
// 출력 결과:// 1. 주문을 받습니다.// 3. 다른 손님의 주문을 받습니다.// (3초 후) 2. ☕ 커피가 완성되었습니다!

------------------------------
## ⚠️ 주의할 점: 콜백 지옥 (Callback Hell)
비동기 처리를 위해 콜백 함수를 너무 많이 중첩해서 사용하면, 코드가 들여쓰기로 가득 차서 가독성이 크게 떨어지는 콜백 지옥 현상이 발생합니다. [8, 9] 
이를 해결하기 위해 최신 자바스크립트에서는 [MDN Web Docs의 Promise](https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Promise)나 async/await 문법을 더 많이 사용하는 추세입니다. [9] 
------------------------------
혹시 특정 라이브러리(예: Node.js, 이벤트 리스너 등)를 공부하시다가 callback()을 보셨나요? 어떤 코드를 작성 중이신지 알려주시면 상황에 맞는 더 정확한 예시를 도와드릴 수 있습니다.
